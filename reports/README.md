## How to read each report

- **Abstract:** a short overview of the project, approach and scope. Read it first to understand what the report covers.
- **Methods:** the model, inputs, algorithm or wiring steps used to produce the output.
- **What was done:** the team's original proposal or course activity, and the separate work represented by this repository.
- **Result and interpretation:** values generated from runnable code, or expected behavior when hardware verification is still pending.
- **Limits and next validation step:** what the diagrams and simulations do not prove, plus the next check needed for real equipment.

The graphics are generated by [the report builder](../tools/build_robotics_reports.py). The cleaning bot hardware is a **proposal**; its map is a **software simulation**. The motor and arm charts are **model outputs**. The fresh Arduino sketch is **not yet verified on hardware**. The PDFs do not reproduce a senior student's report or claim measured lab results.

To rebuild the PDFs, install `reportlab` and `Pillow`, then run `python tools/build_robotics_reports.py` from the repository root.
